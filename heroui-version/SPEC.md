## 1.1 課題分析・機能提案

### 課題
既存の FlowState（`index.html` / `css/styles.css` / `js/app.js` の素のHTML/CSS/JS実装）は、以下の保守負担を抱えている：
- 円形プログレス・スライダー・カードなどのUI部品をすべて自前のCSSで実装しており、見た目の統一感やアクセシビリティ（キーボード操作・ARIA属性）が個別対応任せになっている
- ダークモード切替がクラス手動トグル方式で、CSS変数の重複定義が発生しやすい
- 状態管理がグローバル変数（`timer`, `stats`, `tasks`）＋DOM直接操作で、機能追加のたびに影響範囲の把握コストが増している

### 解決策
同一機能を持つ**別バージョン**を、React + HeroUI（Tailwind CSS + React Aria ベースのコンポーネントライブラリ）で新規に構築する。既存版（ルート直下）はそのまま残し、`heroui-version/` ディレクトリに完全新規プロジェクトとして実装する。両者は独立しており、コード共有・相互依存はない。

### 潜在的課題の提案
- HeroUIはReact専用のため、ビルドツール（Vite）の導入が必須となり、「index.htmlを開くだけ」で動いた既存版に比べ初回セットアップ（`npm install`）が増える
- HeroUIにチャート機能・ドラッグ&ドロップ機能は含まれないため、週間グラフは自作SVGのReact化、タスク並べ替えは `@dnd-kit` の追加導入で補う（ユーザー承認済み）
- LocalStorageのキー名前空間を既存版と分離するため、同一ブラウザで両バージョンを併用してもデータは別管理になる（意図的な設計、ユーザー承認済み）

### 主要機能
- 入力: タスクのテキスト入力、予定ポモドーロ数、タイマー設定（作業/休憩時間のスライダー・プリセット）、テーマ・集中モードの切替、ドラッグ操作
- 処理: ポモドーロタイマーの計測・自動切替、タスクの完了/並べ替え管理、日次・週間統計の集計、日付跨ぎ検知
- 出力: 円形プログレスバー表示、タスク一覧表示、統計サマリーとグラフ表示、デスクトップ通知・通知音・画面フラッシュ
- 外部連携: なし（Web Notifications APIのみ。バックエンド・外部APIなし）
- メンテナンス機能: なし（既存版同様、単純なクライアントサイドアプリ）

## 1.3 機能詳細化 (ブレイクダウン)

### F-01 ポモドーロタイマー
- サブ機能: F-01-1, F-01-2, F-01-3, F-01-4
- **受け入れ基準**:
  - F-01-1（開始/一時停止/リセット）: スタートボタン押下 → タイマーが1秒ごとにカウントダウンし、円形プログレスバーが経過に応じて縮む。ポーズ押下 → カウントダウン停止、残り時間を保持。リセット押下 → 現在モードの設定時間に戻る
  - F-01-2（自動切替）: 作業タイマーが0になる → 「休憩」モードに自動遷移し休憩時間で再カウント開始、完了ポモドーロ数が+1される。休憩タイマーが0になる → 「作業」モードに自動遷移
  - F-01-3（バックグラウンド精度）: ブラウザタブを非アクティブにして作業タイマー稼働中に一定時間経過後、タブに戻る → `targetEndTime`（終了予定時刻）ベースの再計算により、setIntervalの遅延に関わらず残り時間が実時間と一致する
  - F-01-4（完了通知）: タイマーが0に到達 → 通知音再生・画面フラッシュ演出・（通知許可済みの場合）デスクトップ通知が表示される
- **受け渡し基準**: F-01-2でポモドーロ完了時に加算された `pomodoroCount` および完了時刻は、F-04の当日統計（`DailyStat.pomodoros`, `focusTime`）に実際に加算された値として反映される（合成値ではなく、F-01の実処理結果を用いて検証する）

### F-02 タイマー設定
- サブ機能: F-02-1, F-02-2, F-02-3
- **受け入れ基準**:
  - F-02-1（時間スライダー）: 作業時間スライダーを1〜60分の範囲でドラッグ → 表示値が即座に更新され、次回リセット時に新しい時間が反映される（休憩は1〜30分）
  - F-02-2（プリセット）: 「25/5」ボタン押下 → 作業スライダーが25分、休憩スライダーが5分に即座にセットされる
  - F-02-3（集中モード）: 集中モードスイッチON → 設定パネル・統計セクションなど非必須要素が非表示になり、タイマーとタスク一覧のみ表示される

### F-03 タスク管理
- サブ機能: F-03-1, F-03-2, F-03-3, F-03-4, F-03-5
- **受け入れ基準**:
  - F-03-1（追加）: タスク名と予定ポモドーロ数を入力しフォーム送信 → タスク一覧の末尾に新規タスクが追加され、入力欄がクリアされる（テキスト未入力時は追加されない）
  - F-03-2（完了切替）: タスクのチェックボックスをクリック → 該当タスクが完了済み表示（取り消し線等）に変わり、完了タスク数カウンタが更新される
  - F-03-3（並べ替え）: タスクをドラッグして別の位置にドロップ → タスク一覧の順序が入れ替わり、リロード後も順序が保持される
  - F-03-4（表示切替）: 「完了タスクを表示/非表示」ボタン押下 → 完了済みタスクの表示・非表示がトグルされる
  - F-03-5（削除）: タスクの削除ボタン押下 → 該当タスクが一覧から即座に消え、LocalStorageからも除去される

### F-04 統計・週間グラフ
- サブ機能: F-04-1, F-04-2, F-04-3
- **受け入れ基準**:
  - F-04-1（サマリー）: ポモドーロ完了 → 「本日のポモドーロ」「本日の集中時間」「完了したタスク」の各カードの数値が即座に更新される
  - F-04-2（グラフ切替）: 「ポモドーロ数」「集中時間」の切替ボタンを押下 → 週間グラフの縦軸データが対応する指標に切り替わる
  - F-04-3（日付ロールオーバー）: アプリを日付が変わった後に開く（または開いたまま日付をまたぐ） → 新しい日付のデータ枠が週間データに追加され、当日カウンタが0からリセットされる

### F-05 テーマ切替
- サブ機能: なし（単一機能）
- **受け入れ基準**: テーマ切替スイッチをON → 画面全体がダークテーマに切り替わり、リロード後も設定が保持される

### F-06 データ永続化
- サブ機能: なし（横断的関心事）
- **受け入れ基準**: タイマー設定・タスク一覧・統計データ・テーマ・集中モード状態を変更 → ブラウザLocalStorageの `flowstate-heroui:*` キー群に保存され、リロード後に復元される
- **受け渡し基準**: F-03で追加・並べ替え・削除された実際のタスク配列が、F-06の保存処理にそのまま渡され、リロード後に同じ順序・内容で復元される

## 1.5 ユーザー操作シナリオ

1. **インストール**: `heroui-version/` ディレクトリで `npm install` を実行し依存関係を取得
2. **起動**: `npm run dev` でVite開発サーバーを起動しブラウザでアクセス（本番利用時は `npm run build` の成果物を静的ホスティング）
3. **利用**:
   - タスクを1件以上登録
   - タイマー設定（またはプリセット）を選び、スタート
   - 作業→休憩の自動切替を経て、ポモドーロを積み重ねる
   - 完了したタスクにチェックを入れ、必要なら並べ替え
   - 統計セクションで当日・週間の実績を確認
4. **終了**: ブラウザタブを閉じる（状態はLocalStorageに保存済みのため次回起動時に復元）
5. **移設**: `heroui-version/` ディレクトリごと別環境にコピーし、`npm install && npm run build` で再現可能

## 1.6 UI分析・提案

### S-01 メイン画面
既存版と同一のセクション構成を1画面に集約する（ヘッダー / タイマー・設定 / タスク一覧 / 統計）。

> **標準確認観点の適用**:
> - 集計・履歴画面（統計セクション）: 週間グラフは棒グラフでポモドーロ数/集中時間の量を高さで視覚表現する（既存版を踏襲）
> - 全画面共通: 本文フォントはHeroUI/Tailwindのデフォルトフォントスタックを採用し、ユーザー設定は設けない（既存版同様、固定）

主なエラーハンドリング：
- タスク未入力での送信 → フォームのバリデーション（HTML標準の `required`相当、HeroUIの `Input` バリデーション機能を使用）でブロック
- デスクトップ通知の許可が得られない場合 → 通知音・画面フラッシュのみで完了を伝える（既存版と同様のフォールバック）

> **モック**: 本サイクルでは SPEC_DETAIL.md を作成しないため、HTMLモックは省略。実装時に既存版の画面構成・要素配置をそのまま踏襲することでレイアウト認識のズレを防ぐ。

## 1.8 実装概要

- `main.tsx`: `HeroUIProvider` でアプリ全体をラップし、`App` をマウントする
- `App.tsx`: 各カスタムフック（`useTimer`, `useTasks`, `useStatistics`）を呼び出し、状態を各コンポーネントにpropsで渡す。集中モード時の表示切替（F-02-3）もここで制御
- `useTimer.ts`: 既存版 `app.js` のタイマーロジック（`startTimer`/`pauseTimer`/`resetTimer`/`updateTimer`、`targetEndTime`によるバックグラウンド精度補正）をReactの`useEffect`+`setInterval`構成に移植。完了時にF-04向けのコールバックを呼ぶ
- `useTasks.ts`: タスクのCRUD・`@dnd-kit`の並べ替えイベントハンドラを内包し、`order`属性を更新
- `useStatistics.ts`: 既存版の`checkDateChange`/`updateStatisticsDisplay`相当のロジックを移植し、日付跨ぎを検知して`weeklyData`に新規日を追加
- `useLocalStorage.ts`: `flowstate-heroui:` プレフィックス付きキーでのJSON永続化を共通化する汎用フック
- `TimerPanel.tsx`: HeroUIの`CircularProgress`（またはカスタムSVG、既存版の見た目に近い方を実装時に選定）とテキスト表示、`Button`群
- `SettingsPanel.tsx`: HeroUIの`Slider`・プリセット`Button`群・`Switch`（集中モード）
- `TaskList.tsx`/`TaskItem.tsx`: `@dnd-kit`の`DndContext`/`SortableContext`でラップし、HeroUIの`Checkbox`・`Input`・`Button`で構成
- `StatisticsPanel.tsx`: HeroUIの`Card`でサマリー3項目を表示
- `WeeklyChart.tsx`: 既存版の`drawWeeklyChart`ロジックをReactコンポーネント化した自作SVG棒グラフ

## 1.9 メンテナンス・セキュリティ

- ログ出力: 開発時は`console.error`でLocalStorage読み込み失敗等を出力。本番ビルドでの詳細ログは行わない（既存版と同水準）
- デバッグ機能: 専用のデバッグモードは設けない（既存版に準拠）
- セキュリティ対策: 外部通信・バックエンドを持たないため、XSS対策としてタスクテキストの表示はReactの標準エスケープ（`dangerouslySetInnerHTML`不使用）に一任する。LocalStorageは同一オリジンのブラウザ内に閉じるため、既存版同様に機密情報の保存は想定しない
